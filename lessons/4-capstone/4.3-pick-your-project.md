# Lesson 4.3: Pick Your Project

- **Module:** 4 (capstone, shared)
- **Time:** ~20 min
- **Request budget:** ~4 agent requests in the course window (estimate)
- **Last tested:** not yet tested as a script (QA pass 5's improvised run scoped a dissertation sprint planner; the professor wrote the build prompt for the learner, which this script forbids)

## Goal

The learner picks one project, and **scopes it themselves with their own agent**: what it's for, a 20-minute first version, which parts it needs (instructions, skills, memory), what data it touches, and examples of what good looks like.

## Why it matters to a psychologist

Choosing and scoping your own project is the step no course can do for you. It's also where the course's habits pay off: scope before you build (3A.1 / 3B.1), know what data it touches (0.2), and give the AI examples of good (3A.3a).

## Setup

- `lessons/4-capstone/idea-gallery.md`
- The learner's `workspace/capstone/go-live.md` (from 4.2)
- **Coach mode.** The professor offers the gallery and asks questions. **The scoping happens in the agent's window, by the learner.** The professor never writes the brief or the prompt.
- **Where the project lives:** a new skill or memory for their agent lives in the agent's folder. A website, app, or anything that might go public gets **its own folder**, so public files never sit next to private memory (this sets up 4.5).

## UI this lesson depends on

See `lessons/SCREEN_GUIDE.md`: switching windows ⚠️; the microphone ⚠️; pasting screenshots ⚠️.

## Steps

1. **Browse.** Have them open `lessons/4-capstone/idea-gallery.md`. *"Pick one, mash two together, or invent your own."* Let them think. If they're torn, ask: *"Which one would you actually use next week?"*
   - ✅ **Checkpoint:** they've named a project, in a sentence.

2. **Quick check: the recipe.** Ask them to name one thing their project needs for each part. (Example for a CE tracker: the list of credits = **memory**; checking deadlines = **skill**; a calm, brief tone = **instructions**.) Let them do their own.
   - ✅ **Checkpoint:** one item per part, sorted correctly.

3. **Scope it with your agent (agent's window).** Save `progress.md` at "4.3, step 4." Then: *"In your agent's window, tell it what you want to build, in your own words. Ask it to turn that into a short brief: what it's for, what a 20-minute first version looks like, which parts it needs, and what data it touches. Then: what am I missing? Also collect two or three examples of 'good' (links, screenshots, a handout you like) and ask it what makes them good, then correct it. Come back with `/next-step`."* **Pause point.**

4. **Back: the data line.** Ask them to paste **just the brief's "what data it touches" line** (and where the project will live). Check it against `go-live.md`. Flag anything near the line (practicum logs with initials, a work laptop with records).
   - ✅ **Checkpoint:** the data line is consistent with their go-live checklist; a public-facing project has its own folder; they've collected at least two examples of good. If the project touches new data, they add it to `go-live.md`.

5. **Name the moment.** Two sentences: *"You picked it and scoped it yourself, with your agent as a thought partner. That's the whole job: you know what good looks like, and you set the limits."*

## Pause points

- After step 3 (switching to the agent's window).
- End of lesson.

## Done when

They've chosen a project, sorted its needs by part, scoped it with their own agent (brief + examples of good), and the brief's data line matches their go-live checklist.

## Common sticking points

- **The project is too big** ("an agent that runs my whole practice") → *"What's the smallest version you'd use next week?"* The first version is 20 minutes.
- **They want the professor to write the brief** → ask the scoping questions instead (what's it for, what's the first version, what does it touch).
- **The project touches protected data** → it stops here. Help them pick a version that doesn't, or a different idea.

## Avoid

- Don't write the brief, the prompt, or the project choice for them.
- Don't read their agent's folder; ask for the data line.
