# Lesson 3B.2b: Build a Lab Agent: Memory and Handoffs

- **Module:** 3B (lab)
- **Time:** ~20 min
- **Request budget:** ~7 agent requests (estimate; verify in free-tier testing)
- **Last tested:** Antigravity 2.5.5, QA pass 4: passed (the author reached 3B.3a). Revised from the tester's notes; retest in the final end-to-end run.

## Goal

The learner adds two **skills**, `/weekly-lab-update` and a **`/lab-wrap-up` skill that writes a handoff note** to the lab agent's **memory**. They run both in a fresh conversation, refine one by telling the agent what to change, then open another fresh conversation and watch the lab agent pick up where it left off. **Pick up, put down, built into their own agent.**

## Why it matters to a psychologist

Research runs for months, and people come and go: RAs graduate, postdocs move on, you go to a conference and forget what you'd decided. A lab that writes things down survives that. A handoff note is the agent version of a good lab notebook entry: what happened, what's next, what's open.

## Setup

- `world/artifacts/lund-friday-update.md` (Dr. Lund wants a weekly update: done, next, stuck, "three lines is plenty")
- From 3B.2a: `workspace/lab/lab-agent/instructions.md`, `memory/`, `my-papers/`, `lit-matrix.md`, and `.agents/skills/lit-matrix/SKILL.md`. **If they're missing**, go back to 3B.2a first.
- **Firewall (professor):** same as 3B.2a. No papers outside `data/reading-pack/` and the learner's own `my-papers/` file.
- **New skills need a new conversation** (✅ QA pass 4: a skill created in a conversation doesn't show up in that same conversation). So both skills are created first (steps 2–3), then run together in one new conversation (steps 4–5).
- **Less scaffolding from here on (professor):** the learner directs, the agent executes. Let them describe each skill in their own words, then have them ask the agent *"Is anything missing from this?"* Use the lists below as **your** checklist: prompt only for items still missing after that. To refine, ask *"What would you change?"* and offer options only if they're stuck. Changes are made by telling the agent (typed or spoken), not by hand.
- **Pacing (professor):** between ordinary steps, ask *"Ready to move on?"* The only `/next-step`s are at the end of the two side trips (steps 4 and 7). Before each side trip, make sure `progress.md` says which step they're on.
- **Expected weekly update (for the professor):** three short lines, from memory only. **Done:** first-pass lit matrix of six papers (the five-paper pack, three of them on EFT and delay discounting, plus the learner's own). **Next:** read full texts of the three relevant papers; analysis question with Dr. Bello. **Stuck / needs a decision:** "more references" means someone has to find and read real papers first; the pack doesn't support "EFT works for depression."

## Steps

1. **The problem.** *"Your lab agent is smart for one conversation. Close it, and it only knows what's in its files. Today you'll give it two new **skills**, and one of them writes to its **memory**."* Callback: *"Same as `progress.md` for the professor."*
   - ✅ **Checkpoint (knowledge check):** ask *"If your lab agent kept forgetting what you decided last week, which part of the recipe would be missing?"* Expected: **memory**. (Bonus: does it differently every time → skill; ignores how you like things → instructions.)

2. **`/weekly-lab-update`.** Have them open `world/artifacts/lund-friday-update.md`. Then have them describe, in their own words, a skill that writes Dr. Lund's Friday update, and ask the AI to create `.agents/skills/weekly-lab-update/SKILL.md`. Then: ***"Is anything missing from this?"*** (The agent may suggest things on its own too; they decide.) Your checklist: it reads `instructions.md` and `memory/` first; writes **three lines (done / next / stuck)** from memory only, no new claims; saves to `workspace/lab/lab-agent/updates/` with the date. They review it.
   - ✅ **Checkpoint:** read `SKILL.md`. It reads instructions and memory first, and the three-line format is there. One line: *"That's a **skill**."*

3. **`/lab-wrap-up`: the handoff note.** Same move: they describe it, the AI creates `.agents/skills/lab-wrap-up/SKILL.md`, they ask *"Is anything missing?"* Your checklist. When run, it should:
   1. read `instructions.md` and `memory/`;
   2. write `memory/handoff.md`: **what happened this session, what's next, open questions**, with today's date (overwrite the old one, keep it short);
   3. update `memory/projects.md` and `memory/reading-list.md` with anything done or new;
   4. tell the user, in one line, what it saved.

   *Why:* the agent can't remember. It can only read. So it writes down what the next session needs.
   - ✅ **Checkpoint:** read `SKILL.md`. It writes `handoff.md` with the three parts and updates the other memory files. One line: *"Another **skill**, and this one writes the agent's **memory**."*
   - **Pause point** (save their place at step 4 in `progress.md`).

4. **Run both (side trip).** *"New skills show up in a new conversation, so we'll run both there."* **Before they go:** *"Run `/weekly-lab-update` first. When it's done, type `/next-step` there and we'll carry on in that conversation."* New conversation (**+**), `/week` + **Tab** (pick **weekly-lab-update**), send. They review and accept.
   - ✅ **Checkpoint:** read the update and compare with the expected update in Setup. Ask: *"Did it promise anything that isn't in memory?"* (e.g., "five more references found." That would be invented.)

5. **Wrap up, in the same conversation.** Still in this conversation (both skills were created before it started, so both work here): `/lab` + **Tab** (pick **lab-wrap-up**), send. They review the changed memory files before accepting.
   - ✅ **Checkpoint (knowledge check):** before they accept, ask *"You Accept-all `progress.md` after a glance. Why look properly at these memory files?"* Expected, roughly: **memory is what the agent will believe next time**, so a wrong line here gets repeated in every future session. Review before you accept.
   - ✅ **Checkpoint:** read `memory/handoff.md`. It records the matrix and the weekly update as done, and the open questions (more references, the depression claim).

6. **Make it yours.** Ask: *"What would you change about the update or the handoff note?"* Let them answer. Only if they're stuck, offer one or two: a "needs a decision from Dr. Lund" line; a date range ("week of…"); "flag anything older than two weeks." They tell the agent in their own words (typed or spoken); it edits the right `SKILL.md`; they review. *"You directed, it executed. The change shows up the next time the skill runs in a new conversation."*
   - ✅ **Checkpoint:** read the skill file. It has the change they asked for.

7. **Put it down, pick it up (side trip).** **Before they go:** *"When you've seen the result, type `/next-step` there."* New conversation (**+**). Have them ask, in their own words, something like *"What should I work on next for the lab?"* using `/weekly-lab-update` or just plain language. **They shouldn't explain what happened before.**
   - ✅ **Checkpoint:** the answer reflects the handoff note (the matrix is done; full texts and the analysis question are next). If they used `/weekly-lab-update`, it shows their step 6 change too. Ask: *"How did a conversation that never met you know that?"* (Expected: the handoff note in `memory/`, read first by the skill.)

8. **Name the parts.** Ask them to name them this time: *"Which files are your agent's instructions, its skills, and its memory?"* Expected: `instructions.md`; `/lit-matrix`, `/weekly-lab-update`, `/lab-wrap-up`; the `memory/` folder (including `handoff.md`). Then one line: *"The handoff note is the memory part doing what `progress.md` did for you all course."*

9. **Name the moment.** Two sentences: *"You can now stop your lab agent mid-project, close everything, and pick up exactly where you left off, because it writes its own handoff note. And you changed it by telling it what you wanted: you decide, it does the typing."* Teaser: *"In the capstone, you'll make this yours."*

## Pause points

- After step 3 (both skills created, before the side trip).
- End of lesson.

## Done when

`/weekly-lab-update` and `/lab-wrap-up` exist and have run in a new conversation; `memory/handoff.md` has what happened / what's next / open questions; one skill has a change the learner directed; a fresh conversation picked up from the handoff without being told.

## Optional stretch

**`/paper-summary`:** a skill that writes a one-page summary card for a single paper in the pack or `my-papers/` (question, sample, design, finding, limits, "not stated" items), saved to `workspace/lab/lab-agent/summaries/`. Create it, then run it in a **new conversation** on one paper. The same citation rules apply.

## Common sticking points

- **`/lab` or `/week` + Tab shows nothing** → they're probably still in the conversation where the skill was made. Start a new conversation (**+**). Also check the folder name and that `SKILL.md` has frontmatter at the very top.
- **The fresh conversation doesn't know anything** → check the skill's step 1 reads *every* file in `memory/`, including `handoff.md`. If they asked in plain language without a skill, the AI may not have read the lab agent's memory. Try again with `/weekly-lab-update`. Good debugging moment.
- **`/week` + Tab finds the wrong skill** → keep typing (`/weekly-l`) or pick from the list. (If they also did the Clinic path, `weekly-plan` is there too.)
- **The update is long** → Dr. Lund will read three lines. Have them tell the agent to make it three.
- **The update says progress was made that wasn't** → compare it with memory. Agents fill gaps optimistically; the skill should say "from memory only."
- **They're not sure what to change in step 6** → ask what Dr. Lund or Dr. Bello would want to see that isn't there. Offer options only after that.

## Avoid

- No papers outside the reading pack and their own `my-papers/` file (firewall).
- Don't run a skill in the conversation it was created in.
- Don't write the skills' contents for them, and don't make their step 6 change by hand. They direct; the agent edits.
- Don't add more skills than the lesson asks for (the stretch is optional).
- Don't skip the fresh-conversation test. It's the point of the lesson.
