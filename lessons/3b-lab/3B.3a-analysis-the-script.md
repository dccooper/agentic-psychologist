# Lesson 3B.3a: Vibe Code an Analysis: The Script

- **Module:** 3B (lab)
- **Time:** ~25 min (plus Python install time, if needed)
- **Request budget:** ~10 agent requests (estimate; verify in free-tier testing)
- **Last tested:** Antigravity 2.5.5, QA pass 4: passed (the author reached 3B.3a). Revised from the tester's notes; retest in the final end-to-end run.

## Goal

On a real, openly licensed dataset, the learner checks the data dictionary against the data, **has the AI install Python for them, safely** (knowing what, from where, and how to undo it), looks at **who's in the sample**, **writes down the analysis plan before seeing any results**, and has the AI write and run a Python script that answers the one pre-stated question. The work goes into a few clearly explained scripts, so each step is **one command to approve**, not many. Every step goes in a log.

## Why it matters to a psychologist

AI makes analysis fast, and that makes it easy to run twenty tests until one "works." The protections are old ones: decide the question and exclusions first (as in preregistration), use one main test, label everything else exploratory, and know who your sample is before you say what your findings mean. Psychology's replication crisis and its WEIRD-samples problem are both about these habits.

The point of 3B.3b is to compare the learner's agent-made analysis with the published one, blind. If the learner asks what the published result was, say: *"That's next lesson's reveal."* If the AI's analysis seems to "know" the answer, note it; the code is still checkable.
- **Fewer approvals (professor):** ✅ *QA pass 4:* the tester had to approve many small commands while setting up the plan and analysis. After the install, the agent puts the work into **as few scripts as possible**: `check_data.py` (step 4) and `analysis.py` (step 7). Each runs with **one** command. When commands are needed, the agent **groups related ones** into a single command and explains it in one or two sentences, rather than running several small ones. If the agent starts running lots of little commands, ask it to stop and put the work in a script.
- **Pacing (professor):** between steps, ask *"Ready to move on?"* No `/next-step` in this lesson unless there's a side trip.

## Steps

1. **The question comes first.** Have them open `world/artifacts/bello-analysis-plan.md` and read it. Ask: *"What's our one question, and what are we not allowed to do before we've written the plan?"*
   - ✅ **Checkpoint:** they name the question (EFT vs. the two controls on `AUC`) and that exclusions are decided **before** comparing the groups.
   - ✅ **Checkpoint (knowledge check):** ask *"This is real data from real people. Why is it okay to use here, and could you analyze your own lab's participant data this way today?"* Expected: it's **anonymous and openly licensed for reuse** (CC BY, see `data/README.md`); their own participant data **never goes into this tool**. Using AI on real research data is a decision for them, their institution, and their IRB (0.2; the capstone covers it).

2. **Read the dictionary, then check it.** Have them open `data/data-dictionary.md` and skim it. Then have them ask the AI to compare the dictionary with the actual column names in the first line of `data/EFT_Controls.csv` and list every mismatch. (The agent can read both files directly. No commands needed.) *Why:* data dictionaries drift. Finding that out now beats finding it in your results.
   - ✅ **Checkpoint:** compare with the expected mismatches in Setup. They should see at least three, including `Wt.In` vs. `Wt.lbs`. **Ask:** *"Which of these could change an analysis if you got it wrong?"*

3. **Python: let the AI set up your tools.** Have them ask the AI to check whether Python is installed (a read-only check, as in 2.4; one command that checks Python and pip together).
   - **If it's already installed:** say so, and still do the five questions below for the **libraries** step (pip installs software too).
   - **If it isn't: this is a teaching moment.** One or two sentences: *"Setting up tools is one of the most useful things an AI agent can do for you: it knows the commands, so you don't have to. But installing software is a bigger yes than reading a file, so you stay the one who decides."* Have them ask the AI to install Python for them. **Before they approve anything**, the AI answers five questions in plain language, and the learner checks the answers against the command on screen:
     1. **What** is being installed, and why do we need it?
     2. **From where?** (It should be an official source: Python's own site, or the system's package manager, e.g. `winget` on Windows. Not a random download link.)
     3. **What exactly will the command do?** Read it together.
     4. **Does it need administrator rights**, or a password? (Windows may show a "Do you want to allow…" prompt; that's the computer asking, not the AI.)
     5. **How would we undo it?** (Uninstall from Settings → Apps, or the matching uninstall command.)

     Then they approve. Typical paths: **Windows**, the AI proposes `winget install` with Python's official package ID; **Mac**, the AI may suggest the official python.org installer (it opens the download page, and the learner runs the installer) or use Homebrew if it's already there. After installing, open a **new** terminal so Antigravity can find Python.
   - **Then the libraries, in one command.** The AI installs everything the scripts need at once (for example `python -m pip install pandas scipy matplotlib`), with the same five questions, answered briefly. *(pip is Python's own package installer; these are widely used, official packages.)*
   - **Fallback:** if the AI's install fails or they'd rather do it by hand, download the installer from **python.org/downloads** and run it. **On Windows, tick "Add python.exe to PATH"** on the first screen.
   - ✅ **Checkpoint:** a version check prints Python 3.10 or newer, the libraries installed without errors, and they can answer at least *"from where?"* and *"how would we undo it?"* in their own words.
   - **Name the takeaway** (after it works): *"You just had an AI set up software for you, safely: you knew what it was, where it came from, what the command did, and how to undo it. Those five questions work for any install an AI suggests, in this course or anywhere else."*
   - **Pause point** (installs can take a while).

4. **Fewer, bigger steps: one script for the checks.** First, name the tension in two or three sentences: *"You've approved a lot of commands by now. Approving the same safe command over and over is tiring, and tired approval is how mistakes slip through (remember 1.2). The fix isn't switching approval off. It's fewer, bigger, clearly explained steps."*

   Then have them ask the AI, in their own words, for **one** script, `workspace/lab/analysis/check_data.py`, that does two jobs: (a) checks which direction of `AUC` means less discounting, against the `IP` columns (Dr. Bello's rule: don't take the agent's word for it); (b) summarizes who's in the sample (age, sex, race/ethnicity, Hispanic/Latinx, income missing, education) and saves it to `workspace/lab/analysis/sample.md`. **It must not compare the groups on `AUC`.** That's a result, and the plan comes first. The AI explains the script in a sentence or two, then runs it with **one** command they read and approve.
   - ✅ **Checkpoint:** one approval, not several. `sample.md` exists. The AUC direction is right: **higher = less discounting**. No group comparison was computed.
   - ⚠️ *Optional, unverified in the course:* Antigravity's settings have an **Allow list** for terminal commands: under review mode, a command on the list runs without asking. If the learner asks how to get fewer prompts, you may mention it as a **deliberate, narrow** choice: allow only one exact command they understand, such as running their own analysis script. Two cautions in one line each: once a script's command is allowed, later edits to that script run without asking, so they still review the script; and a forum report (2.5.5, Windows) says entries can move after a restart. **Never** suggest auto-approving all commands, Agent-driven development, or Turbo mode. Don't bring the Allow list up unprompted.

5. **Who's in this sample?** Have them open `sample.md`. Ask: *"Who is this data about, and who's missing? Who might these findings later be applied to?"*
   - ✅ **Checkpoint:** compare with the expected sample facts in Setup (75% White, 7% Hispanic/Latinx, US online workers, mean age ≈ 36). They can name at least one group that's under-represented, and that an online US sample isn't a clinical sample.

6. **Write the plan, before any results.** Have them ask the AI to draft `workspace/lab/analysis/analysis-plan.md` from Dr. Bello's email: the question; the outcome (`AUC`) and **which direction means less discounting** (from step 4: higher = less); **exclusions** (what to do with `Manual.Excl` and with `AC.PassBoth`, **and why**); the **one main test**; and "anything else is exploratory." **The learner makes the exclusion decisions**, not the AI. Before they accept: ***"Is anything missing from this plan?"*** Then they direct changes in their own words (typed or spoken). Ask *"What would you change?"* and let them lead.
   - ✅ **Checkpoint:** read the plan. It has all five parts, the AUC direction is right (higher = less discounting), and the exclusion choices are theirs, with a reason each. No results have been computed yet.

7. **The script.** Have them ask the AI to write `workspace/lab/analysis/analysis.py` that follows **their plan exactly**: load the CSV, apply their exclusions, report n per group, run the one main test, and save the results to `workspace/lab/analysis/results.md`. Have them ask the AI to **explain why it chose that test**, and whether the test's assumptions fit an outcome like `AUC`. Then it runs the script with **one** command (they read it, then approve). If something needs fixing, the AI fixes the script and reruns that same command, rather than running loose bits of code.
   - ✅ **Checkpoint:** `results.md` exists. Group sizes match their exclusions (e.g., 62 / 71 / 65 if they removed only `Manual.Excl`). They can say in a sentence what the main test found. **Don't** tell them whether it matches anything published.

8. **The overgeneralization check.** Have them ask the AI for a two-sentence plain-language summary of the result. Then they check it: *does it claim more than this sample supports?* ("People," "patients," "clinically effective," "proves.") They tell the agent how to make it honest about who and what, or rewrite it themselves.
   - ✅ **Checkpoint:** their summary names the sample (US online adults) and doesn't claim clinical effects.

9. **The log.** Have them ask the AI to write `workspace/lab/analysis/analysis-log.md`: every step so far, every decision and why, anything tried and dropped, and anything else labeled **exploratory**. They review it.
   - ✅ **Checkpoint:** the log records their exclusion decisions, the test and why, and labels any extra analyses as exploratory.

10. **Name the moment.** Two sentences: *"You set the question and the rules before you saw a single result, checked the dictionary against the data, and asked who the sample is. The AI wrote the code in minutes, in a few steps you could actually read before approving; your plan is what makes the answer worth anything."* Next lesson: a dashboard, and the reveal.

## Common sticking points

- **"python is not recognized"** after installing → open a **new** terminal (or restart Antigravity). On Windows, rerun the installer and tick **Add python.exe to PATH**. Try `py --version` too.
- **pip errors on a Mac** ("externally managed environment") → usually a Homebrew Python. Use the python.org installer instead, or ask the AI to explain and set up a virtual environment (read the commands first).
- **Lots of approval boxes again** → the agent is running small commands one by one. Have them ask it to put the work in the script and run it once.
- **"Can I just turn approvals off?"** → no. Explain in one line: approval is how you stay in charge of what runs on your computer. The fix is fewer, clearer steps. (The optional Allow list in step 4 is the narrow exception, for one exact command they understand.)
- **The AI offers more tests** ("let's also try…") → fine, but they go in the log as **exploratory**, and they don't change the main question. This is the 20-tests trap.
- **The AI makes the exclusion decision itself** → hand it back: the learner decides, the AI writes it down.
- **They're stuck on the statistics** → the AI can explain the test in plain language. They don't need to master it, just to understand what was tested and why, well enough to write it in the log.
- **They ask what the paper found** → *"That's next lesson's reveal."*

## Avoid

- **Firewall:** don't search for, fetch, name, or describe the published paper, the authors' scripts, or their results. Don't suggest a test because "that's what's usually done with this dataset."
- **Don't open the 3B.3b lesson script before the learner reaches it.** It contains the answer key for the reveal.
- Don't decide the exclusions for them.
- Don't let any result be computed before the plan is written. `check_data.py` checks direction and the sample only.
- Never suggest turning on automatic approval, Agent-driven development, or Turbo mode.
- No dashboard yet. That's 3B.3b.
