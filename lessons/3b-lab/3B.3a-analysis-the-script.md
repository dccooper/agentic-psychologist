# Lesson 3B.3a: Vibe Code an Analysis: The Script

- **Module:** 3B (lab)
- **Time:** ~25 min (plus Python install time, if needed)
- **Request budget:** ~10 agent requests (estimate; verify in free-tier testing)
- **Last tested:** not yet tested

## Goal

On a real, openly licensed dataset, the learner **writes down the question and the analysis plan before seeing any results**, checks the data dictionary against the data, looks at **who's in the sample**, and has the AI write and run a Python script that answers the one pre-stated question. Every step goes in a log.

## Why it matters to a psychologist

AI makes analysis fast, and that makes it easy to run twenty tests until one "works." The protections are old ones: decide the question and exclusions first (as in preregistration), use one main test, label everything else exploratory, and know who your sample is before you say what your findings mean. Psychology's replication crisis and its WEIRD-samples problem are both about these habits.

## Setup

- `world/artifacts/bello-analysis-plan.md` (Dr. Bello's question and house rules)
- `data/EFT_Controls.csv`, `data/data-dictionary.md`, `data/README.md` (real data, CC BY 4.0; 254 anonymous online participants)
- `lessons/2-reusable/2.4-the-terminal.md` (commands are explained before they run)
- **The question (fixed):** do people in the **EFT** group discount delayed rewards less (outcome: `AUC`) than people in the **ERT** and **HIT** control groups?
- **FIREWALL (tutor, critical):** **don't search for, fetch, name, or describe the paper this dataset comes from, or the authors' analysis, or its results.** Don't hint at which test "the authors used." The point of 3B.3b is to compare the learner's agent-made analysis with the published one, blind. If the learner asks what the published result was, say: *"That's next lesson's reveal."* If the AI's analysis seems to "know" the answer, note it; the code is still checkable.
- **Expected facts (for the tutor; these don't depend on analysis choices):**
  - **Rows and groups:** 254 rows, 39 columns. EFT 77, ERT 90, HIT 87.
  - **`AUC` direction:** ranges 0–1; **higher AUC = less discounting** (it rises with the indifference points; correlation with `IP104` ≈ 0.87).
  - **Exclusion columns:** `Manual.Excl` is blank for 198 rows, `Fail.Writing` for 52, `Outside.US` for 4. After removing those: EFT 62, ERT 71, HIT 65. `AC.PassBoth` is "No" for 38 rows overall (11 of the 198); per the dictionary, "No" means they **passed one of two** checks. **Whether to exclude them is a judgment call:** either choice is defensible if it's decided and written down first.
  - **Dictionary vs. data mismatches** (the learner should find at least three): `Avg.Vivid.Elab` / `Avg.Vivid.Check` / `Avg.Freq.Check` in the dictionary are `AvgVivid.Elab` / `AvgVivid.Check` / `AvgFreq.Check` in the data; `Prior.EFT` is `Prev.EFT`; `Wt.In` ("weight in inches") is `Wt.lbs`; `Where.Complete` isn't in the dictionary; the "Avg" check columns are described as medians; `Sex` "Prefer not to respond" appears as `N.A`; and "HIT" means both the control group and, in the `Multitask` entry, the online task itself (likely an Amazon Mechanical Turk "HIT"; that's an inference).
  - **Who's in the sample (all 254):** age 22–81, mean ≈ 36; 136 male, 115 female, 2 other, 1 no answer; race/ethnicity code 6 (White) **191 of 254 (75%)**, Black 26, Asian 13, Hispanic or Latino (race item) 13, multiple 10, American Indian or Alaska Native 1; **Hispanic/Latinx 17 (7%)**; 57 didn't report income; most have a bachelor's degree or more; US residents only, online; mostly completed at home.

## Steps

1. **The question comes first.** Have them open `world/artifacts/bello-analysis-plan.md` and read it. Ask: *"What's our one question, and what are we not allowed to do before we've written the plan?"*
   - ✅ **Checkpoint:** they name the question (EFT vs. the two controls on `AUC`) and that exclusions are decided **before** comparing the groups.

2. **Read the dictionary, then check it.** Have them open `data/data-dictionary.md` and skim it. Then have them ask the AI to compare the dictionary with the actual column names in the first line of `data/EFT_Controls.csv` and list every mismatch. *Why:* data dictionaries drift. Finding that out now beats finding it in your results.
   - ✅ **Checkpoint:** compare with the expected mismatches in Setup. They should see at least three, including `Wt.In` vs. `Wt.lbs`. **Ask:** *"Which of these could change an analysis if you got it wrong?"*

3. **Python.** Have them ask the AI to check whether Python is installed (they did this in 2.4). If it isn't:
   - **Recommended:** download the installer from **python.org/downloads** and run it. **On Windows, tick "Add python.exe to PATH"** on the first screen. Then open a **new** terminal in Antigravity, so it can find Python.
   - **Or:** let the AI install it with a command (on Windows, typically `winget install` with Python's ID). It must explain the command first, and they read it before approving.
   - Then the AI installs the libraries the script needs (for example `python -m pip install pandas scipy matplotlib`). Again: explained first, approved by them.
   - ✅ **Checkpoint:** a version check prints Python 3.10 or newer, and the libraries installed without errors. **Pause point** (installs can take a while).

4. **Write the plan, before any results.** Have them ask the AI to draft `workspace/lab/analysis/analysis-plan.md` from Dr. Bello's email: the question; the outcome (`AUC`) and **which direction means less discounting** (have the AI explain, then check it against the `IP` columns with a quick script; expected: higher = less); **exclusions** (what to do with `Manual.Excl` and with `AC.PassBoth`, **and why**); the **one main test**; and "anything else is exploratory." **The learner makes the exclusion decisions**, not the AI. They review and edit the plan.
   - ✅ **Checkpoint:** read the plan. It has all five parts, the AUC direction is right (higher = less discounting), and the exclusion choices are theirs, with a reason each. No results have been computed yet.

5. **Who's in this sample?** Have them ask the AI to write and run a short script that summarizes the demographics (age, sex, race/ethnicity, Hispanic/Latinx, income missing, education) and saves them to `workspace/lab/analysis/sample.md`. Then ask: *"Who is this data about, and who's missing? Who might these findings later be applied to?"*
   - ✅ **Checkpoint:** compare with the expected sample facts in Setup (75% White, 7% Hispanic/Latinx, US online workers, mean age ≈ 36). They can name at least one group that's under-represented, and that an online US sample isn't a clinical sample.

6. **The script.** Have them ask the AI to write `workspace/lab/analysis/analysis.py` that follows **their plan exactly**: load the CSV, apply their exclusions, report n per group, run the one main test, and save the results to `workspace/lab/analysis/results.md`. Have them ask the AI to **explain why it chose that test**, and whether the test's assumptions fit an outcome like `AUC`. Then it runs the script (they read the command, then approve).
   - ✅ **Checkpoint:** `results.md` exists. Group sizes match their exclusions (e.g., 62 / 71 / 65 if they removed only `Manual.Excl`). They can say in a sentence what the main test found. **Don't** tell them whether it matches anything published.

7. **The overgeneralization check.** Have them ask the AI for a two-sentence plain-language summary of the result. Then they check it: *does it claim more than this sample supports?* ("People," "patients," "clinically effective," "proves.") They rewrite it so it's honest about who and what.
   - ✅ **Checkpoint:** their summary names the sample (US online adults) and doesn't claim clinical effects.

8. **The log.** Have them ask the AI to write `workspace/lab/analysis/analysis-log.md`: every step so far, every decision and why, anything tried and dropped, and anything else labeled **exploratory**. They review it.
   - ✅ **Checkpoint:** the log records their exclusion decisions, the test and why, and labels any extra analyses as exploratory.

9. **Name the moment.** Two sentences: *"You set the question and the rules before you saw a single result, checked the dictionary against the data, and asked who the sample is. The AI wrote the code in minutes; your plan is what makes the answer worth anything."* Next lesson: a dashboard, and the reveal.

## Common sticking points

- **"python is not recognized"** after installing → open a **new** terminal (or restart Antigravity). On Windows, rerun the installer and tick **Add python.exe to PATH**. Try `py --version` too.
- **pip errors on a Mac** ("externally managed environment") → usually a Homebrew Python. Use the python.org installer instead, or ask the AI to explain and set up a virtual environment (read the commands first).
- **The AI offers more tests** ("let's also try…") → fine, but they go in the log as **exploratory**, and they don't change the main question. This is the 20-tests trap.
- **The AI makes the exclusion decision itself** → hand it back: the learner decides, the AI writes it down.
- **They're stuck on the statistics** → the AI can explain the test in plain language. They don't need to master it, just to understand what was tested and why, well enough to write it in the log.
- **They ask what the paper found** → *"That's next lesson's reveal."*

## Avoid

- **Firewall:** don't search for, fetch, name, or describe the published paper, the authors' scripts, or their results. Don't suggest a test because "that's what's usually done with this dataset."
- **Don't open the 3B.3b lesson script before the learner reaches it.** It contains the answer key for the reveal.
- Don't decide the exclusions for them.
- Don't let any result be computed before the plan is written.
