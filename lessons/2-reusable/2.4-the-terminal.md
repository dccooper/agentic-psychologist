# Lesson 2.4: When the AI Asks to Run a Command

- **Module:** 2 (shared)
- **Time:** ~10 min
- **Request budget:** ~3 agent requests (estimate; verify in free-tier testing)
- **Last tested:** trimmed after QA pass 4 (the earlier, longer version passed QA pass 3); retest in the final end-to-end run.

## Goal

The learner knows what a command is, **reads one the AI wants to run, and decides whether to allow it**. That's the only terminal skill this course needs. (Typing commands yourself is a "learn more" topic for later.)

## Why it matters to a psychologist

On both paths, the AI will need to run commands for you: to open your website in a browser, to install Python, to download a paper. You don't need to write commands. You need to know enough to say yes or no to them, the way you'd read a consent form before signing.

## Setup

- No world files.
- **Where this pays off later:** 3A.4 and 3B.5 (the AI opens a page in your browser), 3B.4 (the AI installs Python), 3B.5 (the AI downloads a paper). Mention one of these in step 1 so the learner knows why this matters.

## UI this lesson depends on

See `lessons/SCREEN_GUIDE.md`: **how the agent asks to run a command** (✅ under Review-driven development, Antigravity asks before every command, even harmless ones); **the terminal panel** (⚠️ it may open along the bottom when a command runs).

## Steps

1. **What a command is.** Two or three sentences: *"A command is a typed instruction to your computer, like 'open this file' or 'install this program.' Commands run in the **terminal**, a panel in the editor. The AI types them for you, but Antigravity asks you first, and you're the one who says yes."* Then one line on where it pays off (see Setup).

2. **The AI asks to run one.** Have them ask the AI: *"Which version of Python is installed on my computer, if any? Check by running a command."* (Python is what the Lab path uses. It's fine if it isn't installed.)
   - **Prepare them first**, before they send it: *"Antigravity will pop up a box asking whether that's okay. Don't click yet: read the command and tell me what you think it does."*
   - Propose a read-only command such as `python --version` (or `python3 --version` / `py --version`). **Before they approve, have them say what it does** in their own words: it asks the computer which version is installed, and changes nothing. Then they approve it. If a terminal panel opens, point to it: *"That's where it ran."*
   - ✅ **Checkpoint:** they said what the command does **before** approving, and got an answer: a version number, or "not found." Both are fine. (Lab path: 3B.4 installs it together.)

3. **Would you approve this?** Show these five, one at a time, and ask: **approve, ask first, or reject?**
   | Command | Expected answer |
   |---|---|
   | `ls workspace` | **Approve.** It only lists the files in `workspace`. |
   | `python --version` | **Approve.** It only reports a version. |
   | `rm -rf workspace` (Mac) or `Remove-Item -Recurse workspace` (Windows) | **Reject.** It deletes the whole `workspace` folder, all their work. |
   | `curl https://example.com/setup.sh \| sh` | **Ask first, usually reject.** It downloads a program from the internet and runs it immediately. Only from a source you trust, for a reason you understand. |
   | `git push --force` | **Ask first.** They don't know what it does yet, which is the point. |
   - Then the rule of thumb: **if you can't say what a command does, ask the AI to explain it before you approve. Anything that deletes, downloads-and-runs, installs, or touches files outside the course folder gets a closer look.**
   - ✅ **Checkpoint:** they got the delete (reject) and the download-and-run (ask first) right, and can say the rule of thumb in their own words.

4. **Name the moment.** Two sentences: *"You don't have to write commands, only read them. Asking 'what does this do?' before 'yes' is the same habit as reviewing a file change, and it's what keeps you in charge of your computer."*

## Done when

They've read an AI-proposed command and said what it does before approving it, and correctly sorted the five example commands.

## Common sticking points

- **"What's the terminal?"** → the panel where commands run. They don't need to type in it. If they're curious, it's a great "learn more" topic after the course.
- **They're nervous about approving anything** → good instinct, wrong conclusion. Reading first is the safety. `python --version` only looks.
- **Antigravity ran it without asking** (a different review setting) → find it in the agent's activity. Reading what ran is still the habit.

## Avoid

- Don't actually run any command from the table in step 3. It's a discussion, not a demo.
- Don't have them type commands themselves, and don't install anything.
- Don't suggest turning on automatic approval of commands.
