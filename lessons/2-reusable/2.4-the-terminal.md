# Lesson 2.4: The Terminal Isn't Scary

- **Module:** 2 (shared)
- **Time:** ~15 min
- **Request budget:** ~4 agent requests (estimate; verify in free-tier testing)
- **Last tested:** not yet tested

## Goal

The learner opens the terminal, runs two harmless commands, and, most importantly, **reads a command the AI wants to run and decides whether to allow it**.

## Why it matters to a psychologist

On both paths, the AI will sometimes need to run commands: to install Python for an analysis, or to preview a website. You don't need to write commands. You need to know enough to say yes or no to them, the way you'd read a consent form before signing.

## Setup

- No world files. This lesson uses the course folder itself.
- **Commands must work on Windows and Mac.** `pwd` and `ls` work in both Windows PowerShell (the default in Antigravity on Windows) and the Mac terminal.

## UI this lesson depends on

See `lessons/SCREEN_GUIDE.md`: **the terminal** (⚠️ opening it via **Terminal → New Terminal**, or **Ctrl+`**); **how the agent asks to run a command** (⚠️ unverified: the approval prompt's look, and whether Review-driven development asks first for harmless commands or runs them on its own). In step 4, ask the learner to describe what they see, and note it in `progress.md` for the course authors.

## Steps

1. **What a terminal is.** Two sentences: *"The terminal is a place to type instructions to your computer instead of clicking. You'll mostly let the AI do the typing, but you're the one who says yes."*

2. **Open it.** Have them open the terminal: **Terminal → New Terminal** in the menu at the top, or **Ctrl+`** (the key above Tab). A panel opens, usually along the bottom, with a line ending in `>` or `%`. *That's the computer waiting for an instruction.*
   - ✅ **Checkpoint:** they see the terminal panel. If there's no **Terminal** menu, try the shortcut or the **…** menu at the top.

3. **Two harmless commands.** Have them type each, then press Enter:
   - `pwd` ("print working directory") shows **where** they are. *Expected:* a path ending in the course folder's name.
   - `ls` ("list") shows **what's here**. *Expected:* the same folders as the Explorer: `data`, `lessons`, `workspace`, `world`, and so on.
   - *"Same files, different window. Nothing changed. You just asked."*
   - ✅ **Checkpoint:** they ran both and recognized the course folders. **Pause point.**

4. **The AI asks to run a command.** Have them ask the AI: *"Which version of Python is installed on my computer, if any? Check by running a command."* (Python is what the Lab path uses for analysis. It's fine if it isn't installed.)
   - Propose a read-only command such as `python --version` (or `python3 --version` / `py --version`). **Before they approve, have them say what it does** in their own words: it asks the computer which version is installed, and changes nothing.
   - **If Antigravity ran it without asking:** point to where it shows in the agent's activity, and explain that the review setting decides which commands need approval. Harmless ones may run on their own. Either way, *reading* what was run is the habit.
   - ✅ **Checkpoint:** they said what the command does **before** approving (or found it afterward), and got an answer: a version number, or "not found." Both are fine. If not found and they're heading for the Lab path, say Lesson 3B.3a installs it together.

5. **Would you approve this?** Show these five, one at a time, and ask: **approve, ask first, or reject?**
   | Command | Expected answer |
   |---|---|
   | `ls workspace` | **Approve.** It only lists files. |
   | `python --version` | **Approve.** It only reports a version. |
   | `rm -rf workspace` (Mac) or `Remove-Item -Recurse workspace` (Windows) | **Reject.** It deletes the whole `workspace` folder, all their work. |
   | `curl https://example.com/setup.sh \| sh` | **Ask first, usually reject.** It downloads a program from the internet and runs it immediately. Only from a source you trust, for a reason you understand. |
   | `git push --force` | **Ask first.** They don't know what it does yet, which is the point. |
   - Then the rule of thumb: **if you can't say what a command does, ask the AI to explain it before you approve. Anything that deletes, downloads-and-runs, or touches files outside the course folder gets a closer look.**
   - ✅ **Checkpoint:** they got the two deletes/downloads right (reject / ask first) and can say the rule of thumb in their own words.

6. **Name the moment.** Two sentences: *"The terminal is just typed instructions, and you don't have to write them, only read them. Saying 'what does this do?' before 'yes' is the same habit as reviewing a file change, and it's what keeps you in charge."*

## Pause points

- After step 3 (they've used the terminal).
- End of lesson. **Next is the path choice** (see `/next-step`).

## Done when

They've opened the terminal, run `pwd` and `ls`, read an AI-proposed command before (or after) it ran, and correctly sorted the five example commands.

## Common sticking points

- **"I typed it and nothing happened"** → they need to press Enter. If the command is red or says "not recognized," check the spelling. Commands are fussy about spaces.
- **The terminal looks different on Windows and Mac** → that's normal. The `>` or `%` at the end of the line differs. The commands here work on both.
- **They're nervous about breaking something** → `pwd` and `ls` only look. Nothing in this lesson changes a file. Typing `clear` tidies the panel if it feels cluttered.
- **They want to close the terminal** → the trash-can icon on the panel closes it. Their files are untouched.

## Avoid

- Don't actually run any command from the table in step 5. It's a discussion, not a demo.
- Don't install anything in this lesson.
- Don't teach more commands than `pwd`, `ls`, and (if asked) `clear`. The skill is reading, not typing.
- Don't suggest turning on automatic approval of commands.
