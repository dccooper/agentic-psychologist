# Lesson 3A.2a: Build a Chief of Staff: The Office

- **Module:** 3A (clinic)
- **Time:** ~20 min
- **Request budget:** ~8 agent requests (estimate; verify in free-tier testing)
- **Last tested:** not yet tested

## Goal

The learner builds a working **chief of staff agent** for Dr. Reyes from the three parts: **instructions** (a role file), **memory** (projects and people), and a first **skill** (`/weekly-plan`). They run it and get a weekly plan that fits the real calendar.

## Why it matters to a psychologist

Clinic directors, private-practice clinicians, and supervisors all run on scattered lists. A chief of staff agent is one of the most useful AI projects a clinician can build, and it never needs client information: it organizes *your* work, not your clients' records.

## Setup

- `world/artifacts/reyes-todo-pile.md` (four overlapping to-do lists, typed up by Priya; includes one client callback written safely: "details in chart, not here")
- `world/artifacts/reyes-calendar.md` (week of Monday the 10th; **two events overlap on Wednesday** at 12:30)
- `workspace/clinic/project-brief.md` (the learner's brief from 3A.1, if it exists)
- **How the agent is put together in this course:** the course folder already has an always-on instructions file (`AGENTS.md`, the tutor's). So the chief of staff keeps its own instructions in `workspace/clinic/chief-of-staff/instructions.md`, and **every chief-of-staff skill starts by reading that file and everything in its `memory/` folder.** Same recipe, different files. (In the capstone, 4.1, the learner moves it into a folder of its own, where its instructions become that folder's `AGENTS.md`.)
- **Expected answers for the weekly plan (for the tutor):**
  - **Must flag:** the Wednesday overlap (partners lunch 12:00–1:30 and Jordan's case review 12:30–1:30); the parking permit expiring **Tuesday the 11th**; the budget draft due **Friday the 14th** (suggest Friday 10–12 or Thursday 2–4, both open); the overdue Ward, Locke & Key reply; the Dr. Osei invitation ("this week" was last week).
  - **Must include the personal items:** sister's birthday Saturday the 15th (gift, and a card mailed early enough to arrive), dentist reschedule.
  - **Must not:** schedule tasks during clinical blocks; record any client detail (the callback stays "client callback, see chart").
  - **Duplicates to merge:** budget (three lists), sister's birthday (two), partners lunch prep (two).

## Steps

1. **Meet the pile.** Have them open `world/artifacts/reyes-todo-pile.md` and `world/artifacts/reyes-calendar.md` and skim both. *"Four lists, one calendar, one overloaded director. You're going to build the help Dr. Reyes asked for."*

2. **The recipe.** One line: *"An agent = instructions + skills + memory. Today you'll build all three for the chief of staff, in that order."* Explain the setup note above in one or two sentences: its instructions live in its own folder, and its skills read them first.

3. **Instructions: who it is.** Have them describe the chief of staff's role in their own words: who it works for, what it helps with, its tone, and its limits. Make sure their description covers:
   - it works for Dr. Reyes, on clinic operations **and** personal life;
   - **no client information, ever.** If a task involves a client, it's written as "client callback, see chart," with no names or details;
   - it never sends, books, or deletes anything. It drafts and suggests;
   - it only uses what's in its files and what it's given. If something's unclear, it asks.

   Then have them ask the AI to write that as `workspace/clinic/chief-of-staff/instructions.md`. They review it and make at least one edit by hand.
   - ✅ **Checkpoint:** read the file. It covers all four points, including the client-information rule, and has a learner edit. One line: *"That's the **instructions**."*

4. **Memory: what it knows.** Have them ask the AI to read the to-do pile and create two memory files in `workspace/clinic/chief-of-staff/memory/`:
   - `projects.md`: each open project or task, merged across the four lists, with a due date if one is given;
   - `people.md`: the people Dr. Reyes works with (colleagues and partners only, from the pile and `world/cast.md`).

   They review both before accepting. **Look closely at one thing:** how did it record the client callback?
   - ✅ **Checkpoint:** read both files. Duplicates are merged (budget appears once), dates match the pile, and the callback has **no client details**. `people.md` has no clients. One line: *"That's **memory**: what it knows between sessions."* **Pause point.**

5. **A skill: `/weekly-plan`.** Have them describe what a weekly plan should do, then ask the AI to create `.agents/skills/weekly-plan/SKILL.md` (with `name` and `description` frontmatter, as in 2.3). It should:
   1. read `instructions.md` and every file in `memory/` first;
   2. read the calendar it's given;
   3. pick the top three priorities for the week, with the reason for each;
   4. fit tasks into **open** time only, never clinical blocks;
   5. flag conflicts and anything due or overdue;
   6. include personal items;
   7. save to `workspace/clinic/chief-of-staff/plans/` with the week in the file name.

   They review it closely before accepting (it runs every week).
   - ✅ **Checkpoint:** read `SKILL.md`. Step 1 reads the instructions and memory, and the "open time only" and "flag conflicts" steps are there.

6. **Run it.** **Before they go**, tell them: *"When it's done, type `/next-step` there and we'll carry on."* Then: new conversation (**+**), type `/week` and press **Tab**, attach `@reyes-calendar.md`, send. They review and accept the plan.
   - ✅ **Checkpoint:** read the plan and compare with the expected answers in Setup. Ask them first: *"Did it catch the Wednesday problem?"* If it missed something, use the 2.3 move: ask the AI to compare what it did with what the skill says, and fix the skill.

7. **Name the moment.** Two sentences: *"You built an agent from three parts: instructions that say who it is, memory that says what it knows, and a skill that says how to do a job. It's the same recipe as the tutor that's been teaching you, pointed at Dr. Reyes's week."* Next lesson: giving it a memory that carries over between sessions.

## Pause points

- After step 4 (instructions and memory are built).
- End of lesson.

## Done when

`instructions.md`, `memory/projects.md`, `memory/people.md`, and `.agents/skills/weekly-plan/SKILL.md` exist; a plan for the week of the 10th is saved in `plans/`; it fits the calendar, flags the Wednesday overlap, includes the birthday, and contains no client details.

## Common sticking points

- **The plan schedules tasks during clinical hours** → check the skill says "open time only," and that the calendar was attached. Fix the skill and rerun.
- **The AI records client details for the callback** → there aren't any in the pile, so it's inventing. Point to the instructions rule, and remove it. This is the most important check in the lesson.
- **"Why not just put this in `AGENTS.md`?"** → that file is the tutor's. Two sets of always-on instructions in one folder would mix up the tutor and the chief of staff. In the capstone, the chief of staff gets its own folder.
- **Too much at once** → it's a lot of building. Remind them each part is a file they've made before: instructions (2.1, 2.2), memory (`progress.md`), skill (2.3).

## Avoid

- No client information, real or invented. Don't add any to the examples.
- Don't build `/meeting-prep`, `/whats-slipping`, or `/wrap-up` yet. That's 3A.2b.
- Don't write the role description in step 3 for them.
