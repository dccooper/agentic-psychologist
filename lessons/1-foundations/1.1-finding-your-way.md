# Lesson 1.1: Finding Your Way Around Cursor

- **Module:** 1 (shared)
- **Time:** ~20 min
- **Request budget:** ~8 agent requests (estimate; verify in free-tier testing)
- **Last tested:** 2026-10-24, QA pass 1 (David). Fixes applied; needs a retest.

## Goal

The learner can create a folder and a file themselves, have the AI edit a file, and **review the AI's changes before keeping them**.

## Why it matters to a psychologist

An AI that can change your files is powerful, and you stay in charge by reviewing what it changed. Same idea as reviewing a trainee's note before signing it.

## Setup

- `world/artifacts/jordan-survival-guide.md`
- Interface vocabulary to use consistently: **chat** (where you talk), **Files** (the list of folders and files), **file viewer** (where an open file shows). Name them by label, never by position.

## UI this lesson depends on

See `lessons/CURSOR_UI.md`: the areas of the window; making a folder and a file; **Preview / Source**; the **"N Files Changed" → Review** card. Several of these are still ⚠️ unverified there. If the learner's screen differs, ask what they see, then note it under "Notes" in `progress.md` so the UI map can be fixed.

## Steps

1. **The three areas.** Name them by what they're for, one line each: the **chat** (where we're talking), **Files** (the course's filing cabinet), and the **file viewer** (where a file opens when you click it). Mention that panels can be moved or hidden, so labels matter more than places. Ask them to find each one and tell you what's around it.
   - ✅ **Checkpoint:** they've found all three. If one is missing, help with `CURSOR_UI.md`.

2. **Make a folder.** Have them create a folder named `my-notes` *inside* `workspace`: in the Files list, right-click `workspace` and choose **New Folder**. If that option isn't there, ask what they see (see the UI map's fallback). *Why:* you organize your work, and the AI works inside that organization.
   - ✅ **Checkpoint:** `workspace/my-notes/` exists.

3. **Make a file and type in it.** Have them create `first-week.md` inside `my-notes` and type:
   ```
   # My First Week
   ```
   followed by one line about how they're feeling about starting. Save it (Ctrl+S / Cmd+S). If the file opens formatted and they can't type, have them click **Source**.
   - ✅ **Checkpoint:** the file exists and has their text.

   **Then, a just-in-time explanation of Markdown** (keep it short, after they've typed it):
   > *"The `.md` ending means **Markdown**. It's ordinary text with a few shortcuts for formatting: `#` makes a heading, `-` starts a list item, `**double asterisks**` make bold. AI tools use Markdown for notes, plans, instructions, and documentation because both people and AI can read and edit it easily. Even this course's lessons are Markdown files. That's all you need for now. If you're curious, here's a one-page guide: https://www.markdownguide.org/basic-syntax/"*

   Mention that the **Preview** button shows it formatted, and **Source** shows the plain text underneath.

4. **Read Jordan's guide.** Have them open `world/artifacts/jordan-survival-guide.md` and skim it. It's messy on purpose.

5. **Ask the AI to edit their file.** Have them ask, in their own words, for the AI to turn Jordan's guide into a **clean, prioritized week-1 checklist** and **add it to `first-week.md`** below their own text. Let them try writing the request first. If it's vague, that's fine. Do what they asked, and you can talk about better prompts in 1.3.

   **Don't update `progress.md` in the same turn as this edit.** Keep the change card to just their file, so the review is simple. Update progress after they've reviewed.

6. **Review the change.** This is the key moment of the lesson. Walk them through it **one step at a time**:
   1. *"Under my message there's a card that says **1 File Changed** (or more), listing `first-week.md` with numbers like **+25 −1**. Those are lines added and removed. Click **Review**."*
   2. *"Now check two things: Is your heading and your line about how you feel still there? Is anything from Jordan's guide missing, or did I invent something?"* Don't rely on colors alone. Ask them to read the actual text.
   3. *"Keep the change or undo it using the buttons you see in the review view. What are they called on your screen?"* (Their answer verifies the UI map. Note the labels in `progress.md` Notes.)
   4. If they undo it, help them ask again more precisely ("add it below my text, don't change my text").

   If `progress.md` also appears in the list: *"That's me updating your course bookmark. It's fine to keep."*
   - ✅ **Checkpoint:** the checklist is in `first-week.md`, and they confirmed they reviewed it and chose to keep it.

7. **Name the moment.** Two sentences: *"You just directed an AI to edit a real file, and you checked its work before keeping it. That 'review before you accept' habit is the most important one in this whole course."* Then update `progress.md`.

## Pause points

- After step 3 (folder and file created): a safe break.
- End of lesson.

## Done when

`workspace/my-notes/first-week.md` exists with their own text plus an AI-made checklist they reviewed and kept.

## Common sticking points

- **The file was created in the wrong place** → reassure them. They can drag it into the right folder in Files.
- **No "New Folder" / "New File" option** → ask what the right-click menu shows. Fallback: the **IDE ↗** layout (see `CURSOR_UI.md`). Note what happened for the course authors.
- **They can't type in the file** → it's probably in **Preview**. Click **Source**.
- **They can't find the Review button** → ask them to describe what's under your last message. The **Changes** item in the project panel leads to the same place.
- **The AI overwrote their text** → perfect teaching moment. Show them how to undo it in Review, and ask again with "add below my text, don't change it."
- **"Did I break it?"** → almost nothing in this course can't be undone. Undo (Ctrl+Z / Cmd+Z) works in files too.

## Avoid

- Don't create the folder or file for them. They do steps 2–3 by hand.
- Don't introduce modes or @-mentions yet (1.2 and 1.3), even if they could help.
- Don't silently "fix" their prompt. Do roughly what they asked.
- Don't turn the Markdown note into a tutorial. Three sentences and a link.
