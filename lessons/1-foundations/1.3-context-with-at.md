# Lesson 1.3: Giving the AI Context with @

- **Module:** 1 (shared)
- **Time:** ~20 min
- **Request budget:** ~6 agent requests (estimate; verify in free-tier testing)
- **Last tested:** Antigravity 2.5.5, QA pass 3: passed, no errors. Revised from the tester's notes; retest in the final end-to-end run.

## Goal

The learner can point the AI at the right file with **@**, and write a request with four parts: **context, task, format, constraints**. They've seen the same question get a much better answer when they do.

## Why it matters to a psychologist

A vague referral question gets a vague assessment. The same is true of AI: "summarize this" gets a generic summary, while "who owns what, by when, in a list, and don't guess" gets something you can act on. Asking a clear question is a skill psychologists already have.

## Setup

- `world/artifacts/dept-meeting-transcript.md` (a rambling department meeting with buried action items, two of them with no owner)
- **Expected answers (for the professor; don't show the learner):**
  - Action items with an owner and a date: **Dr. Lund**, send the grant timeline, Wednesday · **Dr. Reyes**, bring referral numbers, next meeting on the 17th · **Priya**, fix the clinic-hours sign, by Monday · **Jordan**, send the orientation schedule to new trainees, by Friday · **Dr. Okafor**, email Facilities for a Procrastination Hall date, tomorrow (the 4th).
  - **No owner:** the coffee machine ("someone should"). **Unclear owner, no date:** a first look at other departments' AI guidance ("one of our new students… no rush").
  - **A decision, not an action item:** meetings go from 90 to 60 minutes starting next month.

## UI this lesson depends on

See `lessons/SCREEN_GUIDE.md`: **@ and /** (typing `@` in the message box to attach a file). ⚠️ *The exact look of the @ file picker is unverified.* If it looks different, ask the learner what they see and note it in `progress.md`.

## Steps

1. **The meeting.** Have them open `world/artifacts/dept-meeting-transcript.md` and skim it. It's long on purpose. *"Imagine you missed this meeting and need to know what you're on the hook for."*

2. **No context.** Have them ask, in their own words, something like *"What were the action items from the meeting?"* **without** pointing to any file.
   - **Honesty note for the professor:** you know which meeting they mean, because you read the lesson. Say so in one line, then answer **only from what their message contains**, the way an AI with no files would: you don't know which meeting, so ask, or give a generic answer. *Why:* in real work, the AI doesn't know what's on your mind or which file you mean.
   - ✅ **Checkpoint:** they see that the answer is a guess or a question back.

3. **Point at the file with @.** Show them that typing **@** in the message box lets them attach a file. Have them ask again with `@dept-meeting-transcript.md` and a short request, e.g. *"@dept-meeting-transcript.md summarize this."* Answer it naturally, the way you would for a short request: a general summary.
   - ✅ **Checkpoint:** they got an answer about the right meeting. Ask: *"Is this what you needed? Could you act on it?"* (Usually: it's accurate, but it's a summary, not a to-do list.)

4. **The four parts.** Introduce the pattern in one line each:
   - **Context:** which file, and who you are ("I'm a new student who missed the meeting").
   - **Task:** exactly what you want ("list the action items").
   - **Format:** what it should look like ("a table: who, what, by when").
   - **Constraints:** the rules ("only from the transcript; if there's no owner or date, write *unassigned*, don't guess").
   Have them write their own request using all four parts, with the @ file, and send it. **They write it, not you.** If they ask for an example, give the four labels above, not a finished prompt.
   - ✅ **Checkpoint:** read the transcript and compare their result with the expected answers in Setup. It should list the five owned items, mark the coffee machine as **unassigned**, and flag the AI-guidance item as unclear. **Pause point.**

5. **Spot the difference.** Ask: *"What changed between the second answer and this one, and which part of your request did it?"* Let them answer.
   - ✅ **Checkpoint:** they connect at least one improvement to one part. (Typical: the table came from *format*; "unassigned" came from *constraints*.)

6. **Catch a guess.** Ask them to check one thing in the result against the transcript themselves: *"Did it give the coffee machine an owner?"* If it did, that's a made-up fact. Have them say so to the AI and get it fixed.
   - ✅ **Checkpoint:** the coffee machine is **unassigned** in the final answer, and they've checked it against the transcript themselves.

7. **Name the moment.** Two sentences: *"Same meeting, same AI, a much better answer, because you told it where to look, what you wanted, how it should look, and what not to do. Context, task, format, constraints works for any request, from a referral letter to a data question."*

## Pause points

- After step 4 (they've written their first four-part request).
- End of lesson.

## Done when

They've asked the same question three ways (no context, @ only, all four parts), connected one improvement to one part of the request, and checked the result against the transcript.

## Common sticking points

- **They can't find the @ picker** → have them type `@` and then the start of the file name, `dept`. If nothing appears, they can type the file's path in the message (`world/artifacts/dept-meeting-transcript.md`). It works the same way.
- **Their four-part request is very long** → fine. Long and clear beats short and vague. It gets shorter with practice.
- **The AI invents an owner or a date** → the best possible outcome for this lesson. Point to the constraint they wrote, then check it against the transcript.
- **"Do I have to write all four every time?"** → no. Use the parts that are missing. In 2.1 they'll save their favorites so they don't have to repeat them.

## Avoid

- Don't write the four-part request for them.
- Don't save anything to `workspace/` yet. Making the action-items file is 1.4.
- Don't use jargon like "prompt engineering" or "context window." "Telling the AI where to look and what you want" is enough.
